为什么可以用 Agent 写 HIL 的代码

现在的电力电子功率变换器，开关频率动辄几十上百 kHz，暂态过程压缩在纳秒量级。 HIL 仿真想把这些行为如实跑出来，步长就得压到 1 µs 以内，而且每一步的时间必须是确定的。

这个要求目前只有 FPGA 才能实现。这也是目前 HIL 仿真器的主流做法:把电路的连续时间模型离散化、定点化，写成 Verilog，综合到 FPGA 上。 这种硬件在环仿真设备的价格动辄几万元，甚至几十万元。他们的软件可以做到拖拽式建模，自动生成 Verilog，用户不需要懂 HDL。

所以用户被迫二选一:

  • 要么买昂贵的商用 HIL 仿真器，省事，但成本高;
  • 要么自己琢磨建模和写 HDL，省钱，但折腾，还不一定准确。

自己写这条路难在哪?把电路的连续时间模型手写成定点、流水化的 Verilog， 这是数字设计的活，大多数做电力电子的人并不熟。指望 AI 帮忙也有问题: VerilogCoder 这类代码生成框架眼里只有离散数字逻辑，既不懂连续物理， 也不管数值稳不稳定，更不知道 HIL 求解器头上还压着硬实时约束。

思路

Agentic HIL 把这件事拆给三个 LLM 智能体分工。Physics Agent 负责把电路拓扑推成状态空间方程，做离散化和定点量化;Hardware Agent 把模型映射成扁平、低延迟的 Verilog，再送去综合;Debug Agent 拿综合后 RTL 的仿真波形跟浮点参考对，发现对不上就自己去改定点数据通路，改到吻合为止。

输入 拓扑 + 指标
→
Physics Agent 状态空间 & Q 格式
→
Hardware Agent Verilog & 综合
→
Debug Agent RMSE & 自动修复
→
输出 经过验证的 HIL 仿真器

它具体能做什么

这三件事单独拿出来，哪一件靠人手工做都够折腾。点开下面几个标签，看看具体自动化掉了什么。

自动搜索定点格式

Physics Agent 会对每个状态变量做静态范围分析，比如电感电流最大能冲到多少， 然后挑一个既不溢出、又不浪费精度的 Q 格式。这活儿以前得工程师拿计算器手算定标， 算大半天;现在是一次自动搜索，电路参数一改就重算一遍。

波形驱动的自动调试

不用人对着 VCD 波形一格一格看。Debug Agent 直接拿 RTL 的仿真输出跟浮点参考比， RMSE 一旦突然变大，基本就是移位没对齐、符号扩展漏了，或者寄存器回绕溢出这几种情况。 它顺着 Verilog 的抽象语法树往回追，定位到出问题的那个算术节点，把数据通路的定义改掉。

Checks: RMSE vs. golden reference Fixes: sign-extension, bit-alignment, overflow

以延迟为先的架构优化

做数字设计的习惯是拿深流水线堆吞吐量，但 HIL 求解器要的恰恰相反: 要压的是单步延迟 tcalc，不是把主频拉高。所以 Hardware Agent 反着来， 把彼此独立的状态方程摊到并行 DSP 上，数据通路尽量保持扁平的组合逻辑， 把延迟压到远小于步长 Δt。

自动时序闭环

框架自己循环调 Vivado:综合完看关键路径够不够 Δt，不够就重新排并行结构。 注意它不会无脑加流水级，那样只会把延迟问题又请回来。 这个循环一直跑到时序收敛、并且还留有余量为止。

你需要准备什么

建模、写代码、调试这些交给智能体，但工具链和硬件还是得你自己备齐:

1
一台工作站 跑 LLM 智能体流水线、Vivado 和仿真工具
2
LLM API 权限 Physics / Hardware / Debug 三个智能体本身都靠 LLM 跑
3
Xilinx Vivado 综合、实现，以及时序闭环那一圈迭代
4
iverilog / yosys 开源 RTL 仿真，AST 波形回溯那步要用
5
一份仿真基准真值 浮点参考模型(比如 PLECS)，Debug Agent 拿它来校验 RTL
6
目标 FPGA 板卡 + 用户手册 比如 Zynq-7020 板卡，手册用来查引脚映射和时钟配置
7
DAC/ADC 子板 + 用户手册 只跑 RTL 仿真用不上，要接真实模拟 I/O 闭环才需要

语法对了，物理不一定对

下面这个例子能说明，为什么这是个物理问题，不是写代码的问题。 这里跑的就是 Buck 的状态空间模型，前向欧拉、50 ns 步长， 跟生成的 RTL 用的是同一套，在你浏览器里实时算出来。

把下面的 DCM 处理 关掉，盯着电感电流看:求解器会一路积分穿过零点， 算出一个负电流。可实际电路里，二极管根本不让电流倒着流。 从这里开始，后面的波形全废了，而 Verilog 语法上一点毛病都挑不出来。 只盯布尔正确性的智能体，就是栽在这种地方。

    结果

    验证平台是一台异步 Buck(24V 降 12V，20 kHz)，参数是特意挑的， 好让它工作在断续导通模式。智能体生成的 RTL 用 Q6.26 定点跑在 Zynq-7020 上， 稳态下跟离线浮点 PLECS 参考只差 16.77 mV，相对误差不到 0.15%。 资源上只占了 4.28% 的 LUT，单步状态更新 10 ns 以内完成， 离 50 ns 的实时预算还差得远。
